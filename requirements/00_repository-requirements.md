# VEXUM教科書｜全体要件定義

## 1. セミナーの目的

**VEXUMの入社前セミナーは、候補者がVEXUMの仕事とAI活用の面白さを理解し、IT・AIの最低限の土台を作り、次の研修へ進むための理解度と学習姿勢を確認する入口である。**

セミナーだけで実務人材を完成させない。開発、CLI、API、GitHub、MCPの技術詳細、正式なセキュリティ実務、常駐ルール等は契約・入社後へ分離する。

## 2. 対象者

- 面接後、契約・入社前のセミナー参加者
- IT・AI未経験者を含む
- RAMとストレージ、ローカルとクラウド等を知らない人がいる前提
- 製品知識の暗記より、全体像・判断・実践を重視

## 3. セミナーの学習導線

セミナー本線は次の順序を基本とする。

1. **Theme 01｜VEXUMとは**
   - 会社と仕事
   - 一般的なITコンサルとの違い
   - 既存ツールか独自開発か
   - 導入・教育・定着・改善まで関わる仕事
2. **Theme 02｜セミナー後の自分のロードマップ**
   - セミナー後に自分がどう進むか
3. **Theme 03｜IT・PCの基礎**
   - PC、ファイル、クラウド、Web、アカウント、権限
   - Google Workspace / Microsoft 365の対応表を5〜10分だけ紹介
   - GUI / CLIを1〜2分だけ紹介
4. **Theme 07｜LLMとは何か**
   - 約4ページを使い、LLMの本質を丁寧に理解する
   - 内部技術用語の暗記はさせない
5. **Theme 08｜実際の生成AIアプリをどう使うか**
   - LLMからAIアプリへの全体図
   - GPT / ChatGPT、Claudeを代表例として短く紹介
   - 通常対話、深い推論、検索、ファイル利用
   - NotebookLMを短く紹介
   - 外部接続は具体例1つ、MCPは一言だけ
6. **Theme 09｜言語化・要件整理・プロンプト**
   - Theme 10で作る家計簿Webアプリの要件書を完成させる
7. **Theme 10｜AIエージェント・バイブコーディング体験**
   - 対話型AIとエージェント型AIの違い
   - Theme 09の要件を使ってGAS家計簿Webアプリを作る
   - 実際に触って改善する
8. **Theme 11｜AI・情報セキュリティ**
   - 情報、権限、出力、外部操作の安全確認
   - 外部Web・ファイル内の不適切な指示への注意

Theme 12以降の詳細業務ツール・開発・API・GitHub等は、原則としてPOST-HIRE / ADVANCED / REFERENCEへ置く。

## 4. 各テーマの役割分担

### Theme 01と02

- Theme 01＝**会社と仕事**
- Theme 02＝**入社後の自分のロードマップ**

会社説明と成長フローを同じテーマで重複させない。

Theme 01ではアジャイル／ウォーターフォールを必須講義にしない。必要な場合も「小さく試して改善する案件と、先に仕様を固める案件がある」程度の補足に留める。

### Theme 03と12

- Theme 03＝**セミナーで必要な業務ツールへの入口**
- Theme 12＝**Google Workspace / Microsoft 365の入社後詳細参照**

Theme 03では対応表を5〜10分だけ扱い、Word / Docs、Excel / Sheets、Drive / OneDrive / SharePointの詳細比較をTheme 12へ分離する。

### Theme 07と08

- Theme 07＝**LLMそのもの**
- Theme 08＝**LLMを使った実際のAIアプリ**

Theme 07ではトークン、Embedding、Transformer、Attention、Training / Inference、RAG、Tool等を個別の学習項目にしない。

Theme 08では最初に、

**LLM → 対話画面 / 検索 / ファイル / 外部接続 / エージェント**

という1ページ程度の全体図を置く。

### Theme 09と10

- Theme 09＝**要件を作る**
- Theme 10＝**その要件で作る・触る・改善する**

Theme 09内で家計簿アプリを実装しない。Theme 10でGAS家計簿Webアプリとして実装体験を行う。

Theme 10ではGUI、CLI、API、GitHub等の技術講義に広げない。GUI / CLIはTheme 03で存在だけ紹介し、詳細はPOST-HIREへ回す。

## 5. AI製品・機能の扱い

### 5.1 代表製品

GPT / ChatGPTとClaudeは、代表的な対話型生成AIの例として短く紹介してよい。

ただし、

- 製品別の全機能説明
- 固定的な優劣ランキング
- 「このAIは必ず○○向け」といった固定分類
- モデル名・料金・UIの暗記

は行わない。

### 5.2 AIの速さと深さ

- 速さを優先する使い方は短い質問・文章修正・簡単な整理等に向く
- 時間をかけて深く考える使い方は複雑な比較・分析・計画等に向く
- 遅いほど必ず正しいわけではない
- 高性能なAIでも自動的にWebを調査するとは限らない

### 5.3 NotebookLM

資料ベースAI活用の具体例として、1ページ以内・5分以内で紹介する。

必須ツールとして操作習得させず、製品名自体をテスト対象にしない。

### 5.4 外部接続・MCP

セミナーでは、

> AIに会社で許可されたGoogle Driveを接続し、指定資料を探して要点をまとめてもらう

程度の具体例を1つ示す。

MCPは「AIと外部ツール・データをつなぐ接続方式の一つ」と一言紹介するだけにする。

API / Connector / MCPの比較・技術仕様はPOST-HIRE / ADVANCEDへ分離する。

## 6. 難易度・文章設計

- 初学者が一度で追える情報量にする
- 専門用語は必要最小限にする
- 平易な説明で足りる場合は専門語を使わない
- 用語暗記より「なぜ必要か」「何が起きるか」を優先する
- セミナーでは内部実装、数式、コマンド、API仕様等へ深入りしない
- 説明だけでなく短いケース・実演・ワークを入れる

## 7. セキュリティ要件

最低限、次を扱う。

- 個人情報、顧客情報、機密情報、認証情報の扱い
- 正しい会社アカウント・利用環境を使う
- 外部サービス接続時の読み取り・書き込み権限
- AI出力の数字・日付・固有名詞・引用等を確認する
- 送信、削除、公開、課金、権限変更、本番変更等では人が確認する
- Webページやファイル内に、AIを誤った方向へ動かそうとする文章が含まれる場合がある

`Prompt Injection`等の専門用語は暗記対象にしない。

会社の正式な情報セキュリティポリシーが教材より優先される。

## 8. 評価要件

理解確認は次を中心にする。

- 自分の言葉で説明する
- 実際に操作・体験する
- ケースを見て判断する
- 理由を説明する
- AIの生成物を評価し修正する

略称・数字・製品名だけを答えさせる暗記問題は原則として使用しない。

## 9. モジュール分類

- **SEMINAR-CORE**：入社前セミナーの本線
- **POST-HIRE**：契約・入社後に習得する実務知識
- **ADVANCED**：技術職・必要者向け
- **REFERENCE**：必要時に参照する詳細資料
- **OPTIONAL**：時間や目的に応じて追加

## 10. 更新性要件

変更されやすい情報は教材公開前に確認する。

- VEXUMの研修・常駐フロー
- AI製品・モデル・UI・料金
- 検索・ファイル・エージェント等の提供機能
- NotebookLM等の製品仕様
- GWS / M365の共有・共同編集仕様
- 社内AI利用・セキュリティ方針

## 11. 情報源の優先順位

1. VEXUMの正式な社内規程・運用ルール
2. VEXUMの確定済み業務フロー・研修方針
3. 各サービスの公式ドキュメント
4. 信頼できる一次情報
5. 旧教科書

旧教科書は参考資料であり、正解として固定しない。

## 12. テーマ共通の完成条件

- 目的が明確
- 到達目標が観察可能
- 必須内容と対象外が分離されている
- セミナー本線に高度な技術が入りすぎていない
- テーマ間で役割が重複していない
- 前後テーマへの接続が明確
- ケース・実演・ワークのいずれかがある
- 暗記依存でない評価方法がある
- 更新対象が明確
- 講師が初学者へ説明できる
