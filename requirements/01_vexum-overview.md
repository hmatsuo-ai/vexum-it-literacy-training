# Theme 01｜VEXUMとは

- 区分：SEMINAR-CORE
- 想定受講段階：セミナー冒頭

## 1. このテーマの目的

受講者が、**VEXUMは何をする会社で、顧客に対してどのような仕事をするのか**を具体的に理解する。

Theme 01は会社と仕事の理解に集中する。受講者自身の研修・契約・NEXUS・常駐までの詳細なロードマップはTheme 02で扱う。

終了時に、受講者が次を自分の言葉で説明できる状態を目指す。

> VEXUMは、AIやITを売ること自体を目的にするのではなく、顧客の現場を理解し、必要な仕組みを選び、導入・改善・定着までつなげる会社である。

## 2. 対象者・前提知識

面接後、契約・入社前のセミナー参加者。前提知識なし。

ITコンサル、SaaS、業務改善、常駐等の言葉を知らない受講者でも理解できる表現を使う。

## 3. 到達目標

- VEXUMの事業・顧客・提供価値を説明できる。
- AIは目的ではなく、売上向上、コスト削減、業務効率化、データ活用等を実現する手段だと理解する。
- 顧客の現場を観察・ヒアリングし、課題を整理してから解決手段を選ぶ仕事だと理解する。
- 独自開発だけでなく、既存SaaS・業務ツールの導入・設定・連携も選択肢になることを理解する。
- 導入して終わりではなく、利用者への説明・教育・定着・改善まで関わる意味を説明できる。
- 一般的なITコンサルの典型的な関わり方と、VEXUMが特に重視する関わり方の違いを説明できる。

## 4. 必須学習内容

### 4.1 VEXUMは何をする会社か

最低限、以下を扱う。

- VEXUMのMission・存在意義
- 顧客の業務課題をAI・ITで改善すること
- 常駐人材が顧客の現場に近い位置で業務を理解すること
- 課題を聞かずにツールや開発へ飛びつかないこと
- 解決策は独自開発だけでなく、既存SaaS・業務ツールも含めて選ぶこと
- 導入・設定・連携・自動化・教育・運用定着までを一続きで考えること
- 成功は「システムを作ったか」ではなく、実際に業務が変わったかで考えること

### 4.2 一般的なITコンサルとの違い

Theme 01の中心的な比較として扱う。

ここでいう「一般的なITコンサル」は、業界全体を一括りに断定するものではなく、プロジェクト型ITコンサルの典型例である。実装・常駐・運用改善まで行う会社も存在するため、違いは**できる／できないではなく、事業モデル上どこに重心を置くか**として説明する。

| 観点 | 一般的なITコンサルの典型 | VEXUMが重視する形 |
| --- | --- | --- |
| 顧客との距離 | 外部の専門家としてプロジェクト単位で支援 | 現場に近い位置で継続的に支援 |
| スタート地点 | ある程度整理された経営・IT課題 | 日々の手作業、属人化、情報分散等の未整理な課題も対象 |
| 解決手段 | 案件に応じて製品選定や開発 | 既存ツールと独自開発を比較し、必要な手段を選ぶ |
| 関わる範囲 | 調査、要件定義、導入支援等 | 現場理解、課題整理、導入・実装、教育、定着、改善までつなげる |
| 成果の考え方 | プロジェクト完遂・要件達成等 | 実際に現場で使われ、業務成果が変わったかを重視 |

#### 最も伝えたいこと

VEXUMで働く人は、単に「AIに詳しい人」になることが目的ではない。

顧客の現場で、

**聞く → 観察する → 課題を整理する → 解決手段を選ぶ → 導入・作る → 使い方を伝える → 結果を見る → 改善する**

という流れに関わる。

### 4.3 既存ツールか独自開発か

「AI会社だから何でもAIで作る」「開発会社だから何でも自作する」という説明にしない。

例えば、既存サービスで十分に解決できるなら、導入速度・費用・保守性の観点から既存ツールを使う方がよい場合がある。一方、業務固有の要件が強ければ独自開発が必要な場合もある。

初心者には、次の判断軸を紹介する程度でよい。

- 必要な機能を満たすか
- 導入までの速さ
- 費用
- 維持・保守のしやすさ
- 現場の人が使いやすいか

### 4.4 「導入して終わり」ではなく「現場が変わるまで」

例：毎月、多数の書類を社員が目視確認している。

1. 何を確認しているのか聞く
2. 現在の業務を見る
3. どこに時間やミスが発生しているか整理する
4. 既存ツールで解決できるか確認する
5. 必要ならAI・自動化・独自開発を組み合わせる
6. 小さく試す
7. 利用者へ使い方を説明する
8. 本当に時間・ミスが減ったか確認する
9. 現場の意見を受けて改善する

この流れをVEXUMの仕事の具体像として見せる。

## 5. セミナーで扱わない内容

- 受講者の契約・研修・NEXUS・常駐までの詳細フロー（Theme 02で扱う）
- アジャイル／ウォーターフォールの比較講義
- 開発手法の用語暗記
- 組織図、役職、料金プラン等の細かな制度説明
- Mission・Vision・Valuesの文言暗記
- 「ITコンサルは資料を作るだけ」等、他社・他業界を不当に単純化する説明
- 「VEXUMだけが現場支援をしている」等の未確認な差別化表現

開発手法に触れる必要がある場合も、セミナーでは「小さく試して改善する案件もあれば、最初に仕様を固めて進める案件もある」程度の1分以内の補足に留める。

## 6. 推奨学習構成

**企業の困りごと → ITコンサルとは → VEXUMが特に重視すること → 既存ツールか開発か → 導入・教育・定着・改善 → ミニケース**

Theme 01の主語は終始「VEXUMと顧客の仕事」とし、「自分の研修ロードマップ」はTheme 02へ渡す。

## 7. 実務ケース

> 社内にExcelや紙の資料が散らばり、問い合わせ対応を毎回ベテラン社員が行っている。経営者から「AIを導入したい」と相談された。

受講者に次を考えさせる。

- まず何を聞くか
- 本当の課題は何か
- 既存ツールで解決できる部分はあるか
- 開発が必要な部分はあるか
- どう小さく試すか
- 利用者にどう使ってもらうか
- 何が変われば成功か

## 8. 理解度確認

暗記ではなく、次を確認する。

1. VEXUMは何をする会社か
2. 一般的なITコンサルの典型と比べ、VEXUMは何を特に重視するか
3. なぜ最初から独自開発と決めないのか
4. なぜ導入後の教育・定着・改善まで重要なのか

## 9. 更新対象情報

- 実際の顧客支援事例・実績数値
