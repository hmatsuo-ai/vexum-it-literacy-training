# Theme 21｜API・Connector・MCP

- 区分：ADVANCED
- 想定受講段階：AIツール・開発基礎後

## 1. このテーマの目的

AIやアプリが外部サービスの情報を読み書きできる仕組みを理解し、API、Connector、MCPを混同せず、権限とデータ範囲を確認して連携を利用できるようにする。

## 2. 対象者・前提知識

Theme 10、13を受講済み。技術担当者はTheme 18、19も推奨。

## 3. 到達目標

- API、Connector、MCPの役割をそれぞれ平易に説明できる。
- 「接続できる」ことと「何を読み書きできるか」を分けて確認できる。
- 認証、権限、スコープ、読み取り／書き込みを意識できる。
- AIエージェントへ外部操作権限を渡すときの確認事項を説明できる。

## 4. 必須学習内容

- API：システム同士が決められた方法で機能・データを利用するための接点
- 認証とAPIキー／OAuthの基本概念。秘密値を教材やコードへ直書きしないこと
- Connector：特定サービスとの接続を利用者が扱いやすくまとめた連携機能という考え方
- MCP：AIと外部ツール・データを接続するための共通的なプロトコル／仕組みという位置づけ
- 読み取りと書き込みの違い
- 最小権限、対象アカウント、対象データ、操作履歴
- 連携解除と権限見直し
- 外部操作の前に人の承認が必要なケース

## 5. 扱わない内容

- MCPをすべてのAPIの代替と説明すること
- Connectorという名称を単一企業固有の意味に限定すること
- 認証情報の実値を教材へ掲載すること

## 6. 推奨学習構成

アプリ間連携 → API → 認証・権限 → Connector → MCP → AIエージェント → セキュリティ

## 7. 実務ケース

AIにGoogle Driveを接続して資料を検索させる場合、接続アカウント、閲覧範囲、書き込み権限、共有先を確認する。

## 8. 演習

「AI → 連携方式 → 外部サービス → データ／操作」の図を作り、各接点の権限と人の承認箇所を記入する。

## 9. 理解度確認

API・Connector・MCPの定義暗記ではなく、提示された連携ケースのリスクと必要権限を説明させる。

## 10. 更新対象情報

MCP仕様、各社Connector名称、提供連携、OAuth権限、API仕様、社内許可サービス。

## 12. 完成条件

受講者が外部連携を「便利だから接続」で済ませず、対象・権限・操作内容を確認できる。
