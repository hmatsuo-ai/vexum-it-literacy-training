# Theme 09｜AIに仕事を伝える｜言語化・要件整理・プロンプト

- 区分：SEMINAR-CORE
- 想定受講段階：Theme 08の次

## 1. このテーマの目的

生成AI時代に重要なのは、長い「魔法のプロンプト」を覚えることではない。

**自分やユーザーが頭の中で思い描いているものを、AIが扱える形まで具体化・言語化し、出来上がったものが本当に使いやすいかを人が判断できること**を中心能力として身につける。

AIに質問させながら一緒に要件を詰める使い方も重要だが、AIはユーザーの頭の中を直接読むことはできない。したがって、人には、

- 何を実現したいのか
- 誰が使うのか
- どんな場面で使うのか
- 何が使いにくいのか
- どのような見た目・体験にしたいのか
- 何を優先し、何を捨てるのか

を考え、言葉・例・画像・資料などで伝える力が必要になる。

バイブコーディングや生成AIによって、コードや成果物そのものをAIが作れる範囲が広がったからこそ、**「何を作るべきかを定義する力」「相手の立場で使いやすさを判断する力」「曖昧なイメージを要件へ変換する力」**の重要性が高まっていることを訴求する。

## 2. 対象者・前提知識

Theme 07「AIとは何か」、Theme 08「生成AIの主要ツールと共通する使い方」を受講済み。

プログラミング経験やデザイン経験は問わない。

## 3. 到達目標

- 頭の中の曖昧なイメージを、AIが作業できる具体的な要件へ変換できる。
- 「何を作るか」だけでなく、「誰が・いつ・何のために使うか」まで整理できる。
- システム、文章、画像など成果物の種類にかかわらず、目的・対象・必要条件・制約・完成イメージを言語化できる。
- AI側に不足情報を質問させ、対話しながら要件を具体化できる。
- AIが作った成果物を、ユーザー視点・目的・使いやすさの観点から評価できる。
- バイブコーディングでは、コードを一から書く能力だけでなく、要件整理・言語化・評価・改善の力が重要であることを説明できる。
- 1回の指示で完成を狙わず、試作 → 評価 → 修正を繰り返せる。

## 4. 必須学習内容

### 4.1 AI時代に重要になる「言語化」

AIは、曖昧な要求からでも何かを生成できる。

しかし、要求が曖昧なままだと、**それらしいが本当に欲しかったものとは違う成果物**ができやすい。

そのため、人の役割は単にAIへ命令文を書くことではなく、頭の中のイメージを分解することにある。

最低限、次を考える。

1. **目的**：何を実現したいか
2. **ユーザー**：誰が使う・見るのか
3. **利用場面**：いつ、どこで、どのように使うのか
4. **必要な機能・情報**：何ができればよいか
5. **優先順位**：何が最も重要か
6. **制約**：してはいけないこと、時間、環境、予算、形式等
7. **完成イメージ**：どのような状態なら「できた」と言えるか

### 4.2 要件定義はエンジニアだけの仕事ではない

生成AI・バイブコーディングでは、コード生成そのもののハードルが下がる。

その結果、初期プロトタイピングでは、

**コードを書く → 作る**

よりも、

**ユーザーの困りごとを理解する → 必要なものを定義する → AIに作らせる → 実際に使って評価する → 改善する**

という流れの重要性が増す。

プログラミング知識が不要になるという意味ではない。技術的な妥当性、安全性、保守性を判断するには技術理解が必要である。

ただし、このセミナーでは特に、**AIが実装を支援できる時代だからこそ、要件を整理する言語化能力とユーザー視点を持つことが価値になる**という考え方を強く伝える。

### 4.3 ユーザー視点｜「動く」と「使いやすい」は違う

システムが動けば完成ではない。

例えば家計簿アプリでも、

- 入力項目が多すぎないか
- スマホから入力しやすいか
- 金額の入力ミスが起きにくいか
- よく使うカテゴリを選びやすいか
- 一覧を見て支出状況をすぐ理解できるか
- 毎日使いたいと思えるか

といった観点が必要になる。

AIが生成した画面を見て、**「ユーザーならどう感じるか」から改善点を出す**ことを必須にする。

### 4.4 AIに質問させて要件を詰める

ユーザー自身も、最初から完璧に要件を言葉にできるとは限らない。

そこでAIに、

> この依頼を実行するために不足している情報を、重要度順に質問してください。

のように依頼し、対話しながら要件を整理する方法を扱う。

重要なのは、**AIに質問させれば人が考えなくてよいわけではない**こと。

AIが出した質問に答えながら、自分でも目的・利用者・優先順位・使いやすさを考える。

### 4.5 システムを言語化する

例：「家計簿Webアプリを作りたい」だけでは不足している。

次のように具体化していく。

- 主な利用者：自分
- 利用端末：スマートフォン中心
- 目的：支出をすぐ記録し、月ごとの使いすぎを把握する
- 必須入力：日付、金額、カテゴリ、メモ
- 保存先：Googleスプレッドシート
- 必要画面：入力画面、支出一覧、月合計
- 重視すること：入力の速さ、見やすさ
- 不要なもの：複雑な会計機能、ログイン機能、多人数共有

このように、**頭の中の「こんな感じ」を仕様へ変換すること**を体験させる。

### 4.6 画像・デザインを言語化する

画像生成でも同じ考え方を扱う。

「かっこいい画像を作って」ではなく、

- 何に使う画像か
- 誰に見せるか
- 主役は何か
- 構図
- 距離・画角
- 光
- 質感
- 色・雰囲気
- 背景
- 入れてほしくない要素

などを具体化する。

ここでもプロンプトテクニックの暗記ではなく、**自分の完成イメージを相手に伝わる形へ分解する能力**を中心にする。

### 4.7 プロンプトの基本構造

プロンプトは、上記の要件をAIへ伝える手段の一つとして扱う。

基本要素は次の通り。

- 目的
- 背景・前提
- 対象ユーザー
- 入力情報
- 必要条件
- 制約
- 出力形式
- 完成条件

RCCO等のフレームワークは整理方法の一つとして紹介してよいが、用語暗記は目的にしない。

### 4.8 AIとの反復

完成までの基本サイクルを、

**イメージを言語化 → AIへ伝える → 試作品を見る → ユーザー視点で評価 → 問題を言語化 → 修正を依頼 → 再確認**

とする。

プロンプトを書くことより、この反復サイクルを回せることを重視する。

## 5. 扱わない内容

- 長いプロンプトほど良いという考え方
- RCCO等を唯一の正解として暗記すること
- 「絶対に精度が上がる魔法の一文」
- 数十個のプロンプトテンプレート暗記
- AIが質問してくれるのでユーザーは要件を考えなくてよい、という考え方
- 「AIがコードを書くのでプログラミング知識は完全に不要」と教えること
- 見た目が生成できた時点でシステムが完成したとみなすこと

## 6. 推奨学習構成

**曖昧なイメージ → 言語化 → AIに質問させる → 要件を整理 → 試作品を作る → ユーザーとして触る → 使いにくさを発見 → 改善内容を言語化 → AIへ修正させる**

「良いプロンプトを書く講義」ではなく、**良い成果物を作るために考え、伝え、評価する講義**にする。

## 7. 実務ケース

### ケース1｜バイブコーディング

依頼：

> 家計簿Webアプリを作って。

まずこの曖昧な指示だけでは、利用者・利用場面・必要機能・UI等が決まっていないことを確認する。

AIに必要事項を質問させ、要件を詰めた後、Theme 08で作成したGAS家計簿Webアプリへ反映する。

完成後はコードを見ることよりも、

- 入力しやすいか
- 迷わず使えるか
- 不要な機能がないか
- 欲しい情報がすぐ見えるか

を受講者自身が利用者として評価する。

### ケース2｜画像生成

依頼：

> AI研修の告知に使う、未来的でかっこいい画像を作って。

という曖昧な依頼から始め、対象者、用途、構図、雰囲気、色、文字を載せる余白等を言語化して、生成結果がどう変わるか比較する。

## 8. 演習

### ワーク｜曖昧な要望を「作れる要件」に変える

受講者に、次のどちらかを選ばせる。

**A：システム**

「学生が使いやすいタスク管理アプリを作りたい」

**B：画像**

「採用イベントで使える魅力的なキービジュアルを作りたい」

次の順で進める。

1. 自分で分かる範囲を言語化する
2. AIに不足情報を質問させる
3. 質問へ回答して要件を更新する
4. AIに試作品を作らせる
5. ユーザー・閲覧者の立場で評価する
6. 使いにくい・イメージと違う部分を言語化する
7. 修正を依頼する

評価は「プロンプトが長いか」ではなく、**完成物の目的適合性と、改善理由を説明できるか**で行う。

## 9. 理解度確認

次を自分の言葉で説明できるか確認する。

1. なぜ生成AI時代に言語化能力が重要なのか
2. バイブコーディングで、要件定義が重要になるのはなぜか
3. AIに質問させる方法にはどんな利点があるか
4. AIが質問しても、人が考える必要が残るのはなぜか
5. 「システムが動くこと」と「ユーザーが使いやすいこと」はどう違うか
6. 画像生成で完成イメージを伝えるには、何を具体化すべきか
7. AIが作ったものをどのように評価・改善するか

## 10. 更新対象情報

- バイブコーディング・エージェント型AIで一般的になっている開発フロー
- AIが利用できる質問・試作・編集機能
- 画像・UI生成等の代表的な利用方法

特定モデル固有のプロンプトテクニックは教材の中心にしない。

## 12. 完成条件

- 受講者がプロンプトを「呪文」ではなく、要件をAIへ伝える手段として理解している。
- 頭の中の完成イメージを目的・ユーザー・利用場面・条件へ分解できる。
- AIに質問させながら要件を具体化できる。
- システムと画像の両方で、曖昧なイメージを言語化する重要性を理解できる。
- AI生成物をユーザー視点で評価し、改善点を言葉にできる。
- バイブコーディング時代に、実装能力だけでなく**要件整理・言語化・ユーザー視点・評価改善の能力が大きな価値を持つ**ことを理解している。
