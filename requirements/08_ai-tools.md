# Theme 08｜生成AIの主要ツールと共通する使い方

- 区分：SEMINAR-CORE
- 想定受講段階：Theme 07の次

## 1. このテーマの目的

生成AIの主要ツールとして、**GPT（ChatGPT）とClaudeを二大ツールとして扱う**。

両者には設計思想、UI、外部連携、モデル特性、細かな機能等の違いはあるが、VEXUMの受講者が日常業務で使うレベルでは、**文章作成、要約、調査補助、資料読解、アイデア出し、コード生成、データ整理など、できることの重なりが非常に大きい**ことを理解させる。

さらに、通常の対話型AIに加えて、**コーディングAIやエージェント型AIでは「質問に答える」だけでなく、複数ステップの仕事そのものを進められる**ことを体験させる。

製品やモデルの暗記ではなく、**目的に応じて「対話型AIで十分か」「エージェント型AIへ仕事を任せるか」を判断できる状態**を作る。

## 2. 対象者・前提知識

Theme 07「AIとは何か」を受講済み。特定のAIサービスの利用経験やプログラミング経験は問わない。

## 3. 到達目標

- GPT（ChatGPT）とClaudeが、VEXUMで扱う主要な生成AIツールであることを理解する。
- GPTとClaudeの基本的な業務能力には大きな重なりがあることを説明できる。
- 両者を固定的な得意・不得意だけで分類せず、実際に試して選ぶ考え方を持てる。
- 生成AIには、応答速度を優先する使い方と、時間をかけて深く考える使い方があることを説明できる。
- AIが外部のデータやツールを使うには接続手段と権限が必要であることを説明できる。
- MCPを、AIと外部ツール・データをつなぐ共通的な仕組みの一つとして説明できる。
- **対話型AIとエージェント型AIの作業プロセスの違いを説明できる。**
- **コーディングAIで、自然言語から動くWebアプリまで作れることを体験する。**
- AIの出力・コード・外部操作をそのまま信用せず、人が確認する箇所を判断できる。

## 4. 必須学習内容

### 4.1 二大ツール｜GPTとClaude

セミナーでは、一般的な生成AIの代表として以下の2つを中心に扱う。

- **GPT / ChatGPT**
- **Claude**

まず次を理解させる。

> **VEXUMの通常業務で使う範囲では、GPTとClaudeで「できること」の違いは比較的小さい。**

どちらでも、主に以下のような業務ができる。

- 質問・壁打ち
- 文章作成・修正
- 要約
- 資料読解
- アイデア出し
- 調査の補助
- 表・データの整理
- コード生成・修正
- 要件整理
- 提案や資料のたたき台作成

### 4.2 GPTとClaudeの違いの扱い方

GPTとClaudeに違いがないという意味ではない。

違いが出やすい要素として、次を紹介する。

- 回答の表現や傾向
- モデルや推論モード
- ファイル・資料の扱い方
- Web検索・リサーチ機能
- コーディング支援機能
- 外部サービスとの連携
- UIやワークフロー
- 利用可能な会社契約・権限

ただし、これらは更新が速いため、**「GPTは必ず○○向き」「Claudeは必ず○○向き」と固定しない。**

基本姿勢は、

**同じ仕事を両方に試す → 出力・使いやすさを比較する → その時点で適切な方を選ぶ**

とする。

### 4.3 速さと深さのトレードオフ

- **軽量・低推論**：短い質問、文章修正、単純な整理などに向く。
- **高性能・高推論**：複雑な条件整理、比較、分析、計画、難しい問題などに向く。
- **リサーチ・外部ツール利用**：Webや接続資料を確認するため通常対話より時間がかかるが、外部情報を使える。

重要なのは、**「遅いほど必ず正しい」「高性能なら必ず調査する」という意味ではない**こと。

### 4.4 AIが回答・作業を行う方法の違い

同じ生成AIでも、次のように使い方が異なる。

- 質問だけで回答する
- 渡されたファイルや資料を読む
- Web等の外部情報を検索する
- 接続された業務サービスから情報を取得する
- 外部ツールを使って処理・操作する
- 複数の作業を計画し、順番に実行する
- コードやファイルを直接編集する

「AIが知っていること」「AIが今確認したこと」「AIが実際に操作したこと」を区別する。

### 4.5 AIと外部サービスの接続

外部サービスを利用する場合は、次を確認する。

1. 何のサービスへ接続するか
2. どのアカウントで接続するか
3. 何のデータを読めるか
4. 書き込み・送信・削除などの操作が可能か
5. 人の承認が必要か

### 4.6 MCPの基本概念

MCPは、**AIが外部のツールやデータを利用するための共通的な接続方法・ルールの一つ**として扱う。

初心者には、

**AI ↔ MCP等の接続手段 ↔ 外部ツール・データ**

という関係で説明する。

MCPそのものの暗記ではなく、**AIに外部の情報や操作能力を追加するには接続方法と権限管理が必要**という本質を理解させる。

### 4.7 共通する安全確認

- 個人情報・機密情報を入力してよい環境か
- 接続先アカウントが正しいか
- AIが参照した情報源を確認できるか
- 送信・削除・公開等の操作前に内容を確認したか
- 数字、固有名詞、日付、根拠を人が確認したか
- AIがコードやファイルを変更した場合、何が変更されたかを確認したか

### 4.8 紹介コラム｜NotebookLM

NotebookLMは、**自分が指定した資料を中心に質問・要約・比較・整理する「資料ベースのAI活用」の代表例**として紹介する。

- PDF、Webページ、文書等の資料をまとめて扱える。
- 与えた資料を中心に質問・要約・比較できる。
- 回答の根拠を元資料へ戻って確認する使い方に向く。
- GPTやClaudeでも類似の資料読解は可能であり、NotebookLMだけができることとして教えない。

位置づけは**必須ツールではなく、知っておくと便利な選択肢の一つ**とする。

### 4.9 対話型AIとエージェント型AI

#### 対話型AI

基本は、

**人が質問・指示 → AIが回答 → 人が次の指示**

を繰り返す。

コード作成の場合も、AIがコードを回答し、人がコピー・実行・エラー確認を行うことが多い。

#### エージェント型AI

人がゴールと条件を与えたあと、AIが必要な作業を分解し、利用可能なツールを使いながら複数ステップを進める。

イメージは、

**人がゴールを伝える → AIが計画する → ファイルを確認する → コードを書く → 実行・修正する → 結果を報告する**

である。

すべてを完全自律で任せることを目的にせず、**どこまでAIに任せ、どこで人が確認・承認するか**を理解させる。

### 4.10 コーディングAI｜こんなことまでできる

コーディングAIは、単にコード例を返すだけでなく、環境によっては次まで行える。

- 既存コードを読む
- 複数ファイルを編集する
- 新しいファイルを作る
- エラーを確認する
- コードを修正する
- UIを変更する
- 要件に合わせて機能を追加する
- 成果物全体を見ながら修正する

ここではプログラミング文法の暗記より、**「何を作りたいか」「どう動いてほしいか」を自然言語で要件化する能力の重要性**を伝える。

## 7. 実演

### 実演1｜同じ業務をGPT・Claudeに依頼する

同一の業務課題をGPTとClaudeの両方へ依頼する。

例：

> 顧客との会議メモから、課題・確認事項・次のアクションを整理してください。

目的は勝敗をつけることではなく、**両方で同じ種類の仕事ができる**ことを確認すること。

### 実演2｜コーディングAIで動くものを変更する

既存の簡単なWebアプリ等をコーディングAIへ渡し、自然言語だけで次のような変更を依頼する。

- 入力欄を追加する
- 合計金額を自動計算する
- 表示をスマホ向けに整える
- エラーを修正する

**AIが「コードを説明する」だけでなく、成果物自体を変更できる**ことを見せる。

## 8. メインワーク｜GASで家計簿管理Webアプリを作る

### 8.1 ワークの目的

**対話型AIとエージェント型AIでは、同じ「Webアプリを作る」という仕事でも作業の進み方がどう違うか**を体験する。

GASやJavaScriptの文法を覚えることは目的にしない。

成果物として、Google Apps Scriptを使った簡単な**家計簿管理Webアプリ**を作る。

### 8.2 最低限のアプリ要件

- 日付を入力できる
- 金額を入力できる
- カテゴリを選べる
- メモを入力できる
- 登録した支出を一覧表示できる
- 合計金額を表示できる
- データをGoogleスプレッドシートへ保存できる

余裕があれば、月別集計、カテゴリ別集計、グラフ等を追加する。

### 8.3 前半｜対話型AIで作る

GPTまたはClaude等へ家計簿Webアプリの要件を伝える。

典型的な流れ：

**要望を伝える → コードを受け取る → 人がGASへ貼り付ける → 実行する → エラーをAIへ伝える → 修正版を受け取る**

このとき、人がどれだけ中継・操作しているかを意識させる。

### 8.4 後半｜エージェント型AIで作る

利用可能なエージェント型・コーディングAI環境へ同じ要件をゴールとして渡す。

AI側が、

- 必要な構成を考える
- ファイル・コードを作る
- 複数箇所を整合させる
- 修正をまとめて行う

流れを観察する。

GASへの直接デプロイまで自動化できない環境でも、**コードを一つずつ受け取る対話型AIと、成果物全体を扱うエージェント型AIの違い**が理解できればよい。

### 8.5 比較する観点

| 観点 | 対話型AI | エージェント型AI |
|---|---|---|
| 人の指示 | 1ステップずつ出すことが多い | ゴール・制約をまとめて渡しやすい |
| 作業分解 | 主に人が行う | AI自身が計画・分解できる |
| コードの扱い | 回答されたコードを人が移すことが多い | ファイル・既存コードを直接扱える場合がある |
| 修正 | 人がエラーを伝えて再質問する | AIが確認・修正まで進められる場合がある |
| 人の役割 | 操作・中継・細かな指示が多い | 要件定義・確認・承認の比重が上がる |

重要なのは、**エージェント型AIの方が常に優れているわけではない**こと。

小さな質問なら対話型AIの方が速いこともあり、複数ステップの開発・調査・ファイル編集ではエージェント型AIが有効になりやすい、という使い分けを理解させる。

### 8.6 振り返り

完成したアプリのコード量や見た目ではなく、次を考えさせる。

1. 自分はAIへ何を伝えたか
2. AIはどこまで自分で作業したか
3. 人が行った作業は何だったか
4. どこで確認・修正が必要だったか
5. 顧客から曖昧な要望を受けた場合、最初に何を確認すべきか

この振り返りをTheme 09「プロンプト／要件整理」へ接続する。
