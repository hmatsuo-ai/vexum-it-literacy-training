# Theme 12｜AIエージェント・バイブコーディング

- 区分：ADVANCED / OPTIONAL
- 想定受講段階：AI基礎・プロンプト習得後

## 1. このテーマの目的

AIに「答えを返してもらう」使い方から一歩進み、AIに仕事の手順を分解・実行させる考え方と、自然言語を使った開発の利点・危険性を理解する。

その前提として、**PCにはGUIとCLIという代表的な操作方法があり、AIエージェントも画面・ブラウザを操作したり、ターミナルからコマンドを実行したりしてPC上の作業を進められる**ことを理解する。

GUI・CLIを使いこなすこと自体はこのテーマの目的にしない。「PCは画面上のボタンだけで動いているのではなく、同じファイルやプログラムを異なる方法で操作できる」という基本構造を理解させる。

## 2. 対象者・前提知識

Theme 09〜11を受講済み。開発経験は必須としない。

GUI、CLI、ターミナル、コマンドといった用語を知らない受講者を前提にする。

## 3. 到達目標

- GUIとCLIの違いを初学者向けの言葉で説明できる。
- GUIとCLIは別々のPCではなく、同じPC・OS・ファイル・プログラムを異なる方法で操作するための入口であることを理解する。
- ターミナルがCLIを利用するための代表的なアプリであることを理解する。
- AIエージェントが、ブラウザ等のGUI操作やターミナル等のCLI操作を使って仕事を実行する場合があることを理解する。
- 対話型AIとAIエージェントの違いを説明できる。
- 「目的 → 計画 → ツール利用 → 実行 → 確認」の流れを理解できる。
- 人が承認すべきポイントを含めた簡単なエージェント業務フローを設計できる。
- バイブコーディングで生成されたコードを無確認で本番利用してはいけない理由を説明できる。

## 4. 必須学習内容

### 4.1 PCを操作する2つの代表的な方法：GUIとCLI

最初に、エージェントの説明へ入るためのPC基礎として扱う。

#### GUI（Graphical User Interface）

- 画面上のウィンドウ、アイコン、ボタン、メニュー等を見ながら操作する方法
- マウス、トラックパッド、タッチ操作等を使う
- Finder、エクスプローラー、Webブラウザ、各種アプリ等が身近な例
- 普段PCを使うときに多くの人が触れている操作方法であること

#### CLI（Command Line Interface）

- 文字で命令を入力し、PCやプログラムを操作する方法
- macOSのターミナル、Windows Terminal等から利用することが多い
- `cd`、`ls`、`mkdir`等のコマンド名を暗記させることは目的にしない
- 「文字で指示すると、その指示に従ってファイル操作やプログラム実行等が行われる」という仕組みだけ理解させる

#### 最も重要な理解

GUIとCLIは、まったく別の世界ではない。

例えばフォルダを作る場合、

- GUI：Finderやエクスプローラーで右クリックして「新規フォルダ」を選ぶ
- CLI：ターミナルからフォルダ作成を指示する

という違いがあるが、**最終的には同じPC上にフォルダが作られる**。

この対応関係を通じて、PCには「人が画面を見て操作する方法」と「文字で直接指示する方法」があることを理解させる。

### 4.2 GUI・CLIとAIエージェントの関係

AIエージェントは、回答文を生成するだけでなく、許可されたツールを使って実際の操作を行う場合がある。

代表例として以下を紹介する。

- ブラウザを開く、ボタンを押す、フォームへ入力する → GUIに近い操作
- ファイルを探す、プログラムを実行する、開発ツールを操作する → CLIを利用する場合がある
- 外部サービスへ直接データを送受信する → API等を利用する場合がある

ここではAPIとの技術的な違いまで深掘りしない。

重要なのは、**エージェントは「PCの中に入って魔法のように仕事をする」のではなく、GUI・CLI・API等の利用可能な入口を使って処理を実行している**というイメージを持たせることである。

### 4.3 対話型AIとエージェント型AI

- 対話型AIとエージェント型AIの違い
- タスク分解、ツール利用、状態・履歴、反復、完了判定
- 人の承認を挟むHuman-in-the-loop
- 失敗時の停止条件とエスカレーション
- 権限を持つエージェントほどリスクが高くなること

### 4.4 バイブコーディング

- バイブコーディングの概念
- AIにコード生成を任せる場合の仕様・テスト・レビューの必要性
- Git等で変更履歴を残す考え方

## 5. 扱わない内容

- GUIの全機能やショートカットの習得
- CLIコマンドの暗記
- ターミナルを自在に操作できることを到達条件にすること
- シェル、PATH、環境変数等の技術的な詳細
- エージェントなら完全自律で安全に動くという説明
- 「コードを読めなくても本番システムを作れる」という断定
- 特定サービスの機能一覧の暗記

## 6. 推奨学習構成

PCはどう操作されているか → GUI → CLI → 同じ操作をGUI／CLIで見比べる → エージェントがGUI・CLI等を使うイメージ → 対話型AI → エージェント → 実行フロー → 人の承認 → バイブコーディング → 安全な開発

GUI・CLIの説明は長い操作研修にせず、**エージェントを理解するための前提知識として短く扱う**。

## 7. 実務ケース

### ケース1：GUIとCLI

「新しいフォルダを作る」という同じ結果について、GUIで行う場合とCLIで行う場合を講師が見せる。

受講者にはコマンドを暗記させず、

- 操作方法は違う
- 最終的にPC上で起きていることは同じ

という点を確認させる。

### ケース2：AIエージェント

毎週の報告書作成を「情報取得 → 要約 → 下書き → 人による確認 → 送信」に分解し、どこまでAIに任せるかを設計する。

その際、「ブラウザから情報を見る」「ファイルを読む」「処理を実行する」等、エージェントがどの入口を使って作業しているかも簡単に考えさせる。

## 8. 演習

### 演習1：PC操作の入口を見分ける

次のような操作例を見て、GUI・CLIのどちらに近いかを分類する。

- ブラウザのボタンをクリックする
- Finderでファイルを移動する
- ターミナルへ文字で指示する
- コマンドからプログラムを実行する

正確な専門知識より、操作方法の違いを理解できているかを見る。

### 演習2：エージェント業務フロー

1つの定型業務について、開始条件、AIの作業、利用ツール、人の承認、失敗時処理、完了条件を図にする。

## 9. 理解度確認

以下を確認する。

1. GUIとCLIの違いを簡単に説明できる。
2. GUIとCLIで方法が違っても、同じPC上のファイルやプログラムを操作できることを理解している。
3. なぜAIエージェントの説明でGUI・CLIの理解が役立つのか説明できる。
4. 自動化できることではなく、「どこに人の確認を置くべきか」とその理由を説明できる。

CLIコマンドを覚えているかどうかは評価しない。
