# Theme 10｜AIエージェント・バイブコーディング体験

- 区分：SEMINAR-CORE
- 想定受講段階：Theme 09の次

## 1. このテーマの目的

Theme 09で作った家計簿Webアプリの要件を使い、**AIに実際の成果物を作らせ、触って評価し、改善する体験**を行う。

セミナーではGUI、CLI、API、GitHub等の技術講義には広げない。

伝える中心は、

1. 対話型AIは主に回答や成果物を返す
2. エージェント型AIは複数の作業を順番に進めることがある
3. バイブコーディングでは自然言語からアプリの試作品を作れる
4. AIが作ったものは、人が触って確認・改善する必要がある

という流れである。

## 2. 到達目標

- 対話型AIとエージェント型AIの大まかな違いを説明できる。
- AIへ要件を渡し、試作品を作らせる流れを体験する。
- Theme 09の要件書を使ってGAS家計簿Webアプリの試作品を作る。
- 「動いたから完成」ではなく、ユーザー視点で使いやすさを評価できる。
- 改善点を言語化し、AIへ修正を依頼できる。
- AIが生成したコード・設定・操作を無確認で本番利用してはいけないと理解する。

## 3. 必須学習内容

### 3.1 対話型AIとエージェント型AI

初心者には次の違いだけ扱う。

#### 対話型AI

- 質問へ答える
- 文章やコードを作る
- 人が次の指示を出しながら進める使い方が中心

#### エージェント型AI

- 目的を受け取り、必要な作業を複数ステップに分けて進める場合がある
- ファイル確認、調査、編集、実行等を組み合わせることがある
- 途中で人の確認・承認が必要になる場合がある

重要なのは、**エージェント＝完全自動で正しく仕事を終える仕組みではない**こと。

### 3.2 バイブコーディングとは

日本語等で、

- 何を作りたいか
- どんな人が使うか
- 何ができればよいか
- どんな見た目・使い方にしたいか

を伝え、AIに実装を支援させる考え方として扱う。

コード文法の講義にはしない。

Theme 09で作った要件が、実際の生成結果にどう影響するかを見ることを重視する。

### 3.3 メイン実演・ワーク｜GAS家計簿Webアプリ

Theme 09で作成した要件書をAIへ渡す。

基本構成は、

- Googleスプレッドシートを保存先にする
- GASでWebアプリとして動かす
- スマートフォンから支出を入力できる
- 日付、金額、カテゴリ、メモを保存する
- 支出一覧または月合計を確認できる

程度とする。

GASやコードそのものを理解することはセミナーの合格条件にしない。

講師側で安全なサンプル環境・テンプレートを用意し、受講者は**AIへ要件を伝えて試作品を作る体験**に集中する。

### 3.4 作ったものを実際に触る

試作品が動いたら、受講者自身がユーザーとして操作する。

確認例：

- スマホから入力しやすいか
- 入力項目が多すぎないか
- 金額やカテゴリを間違えにくいか
- 保存されたことが分かるか
- 月の支出をすぐ確認できるか
- 不要な機能がないか

### 3.5 改善点を言語化して修正する

Theme 09で学んだ言語化を再利用する。

例：

悪い修正依頼：

> もっと使いやすくして。

良い修正依頼：

> スマホで片手入力しやすくするため、金額入力欄を最上部に置き、カテゴリはプルダウンで選べるようにしてください。保存後は入力完了が分かる表示を出してください。

**要件整理 → 実装 → 操作 → 評価 → 修正**の循環を体験する。

### 3.6 安全な範囲で試す

セミナーの実装は練習用環境に限定する。

- 実際の顧客情報を使わない
- 本番システムを直接変更しない
- AIが作ったコードを無確認で重要環境へ適用しない
- 外部送信・削除等の影響が大きい操作は行わない

詳細なセキュリティ判断はTheme 11で扱う。

## 4. 扱わない内容

- GUI / CLIの詳しい説明（Theme 03で短く紹介済み）
- CLIコマンドの暗記
- APIの仕組み
- MCPの仕組み
- Git / GitHubの操作
- GAS・JavaScript・HTMLの文法講義
- 本格的な開発環境構築
- 本番システムへのデプロイ手順
- AIが生成したコードの高度なレビュー方法

これらは入社後・技術研修へ分離する。

## 5. 推奨学習構成

**対話型AI → エージェント型AI → Theme 09の要件書を渡す → AIにGAS家計簿アプリを作らせる → スマホで触る → 不満点を言語化 → AIへ修正依頼 → 再確認**

## 6. 演習

### ワーク1｜作る

Theme 09の要件を使い、講師の用意した環境で家計簿Webアプリの試作品を作る。

### ワーク2｜評価する

利用者として実際に触り、改善点を最低2つ出す。

### ワーク3｜改善する

改善点を具体的な修正要件へ変換し、AIへ修正を依頼する。

## 7. 理解度確認

次を確認する。

1. 対話型AIとエージェント型AIの違いを大まかに説明できる。
2. Theme 09の要件がTheme 10の生成結果にどう影響したか説明できる。
3. 「動く」と「使いやすい」の違いを説明できる。
4. AIが作ったものを確認せず本番利用してはいけない理由を説明できる。
5. 利用者視点の改善点を言語化できる。
