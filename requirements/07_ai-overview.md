# Theme 07｜AIとは何か

- 区分：SEMINAR-CORE
- 想定受講段階：Theme 02の次

## 1. このテーマの目的

AIを難しい技術用語として覚えるのではなく、**「AIはどのような仕組みで動き、なぜそれらしい回答ができるのか。その一方で、なぜ間違えるのか」**まで理解する。

特にLLMについて、単なる製品説明ではなく、**入力された文章がトークンに分かれ、文脈を参照しながら次に続く可能性の高いトークンを予測し、それを繰り返して文章を生成している**という基本構造を理解させる。

そのうえで、AIの得意・不得意、人との役割分担、仕事での使い方へつなげる。

## 2. 対象者・前提知識

Theme 01〜02を受講済み。AI経験は問わない。

数式や機械学習の専門知識は前提にしないが、仕組みをブラックボックスのまま使わせない。

## 3. 到達目標

- AI・生成AI・LLMの関係を説明できる。
- LLMが「巨大な知識データベースから正解を検索している」のではないことを理解する。
- トークン、Embedding、次トークン予測、コンテキスト、Attentionの役割を初心者向けの言葉で説明できる。
- 学習時と利用時（推論時）の違いを説明できる。
- なぜLLMが自然な文章を生成できるのかを説明できる。
- なぜハルシネーションが起こるのかを、仕組みと結び付けて説明できる。
- AIに任せる部分と、人が判断・確認する部分を分けて考えられる。

## 4. 必須学習内容

### 4.1 AI・生成AI・LLMの関係

- **AI**：認識、予測、生成、判断補助などをコンピュータで行う技術の総称
- **生成AI**：文章・画像・音声・動画・コード等を新しく生成するAI
- **LLM（Large Language Model）**：大量の文章から言語のパターンを学習し、文章理解・生成を行う大規模言語モデル

LLMは生成AIの一種であり、ChatGPT、Claude、Gemini等の対話型AIの中核として使われることが多い。

### 4.2 トークン｜AIは文章をそのまま読んでいない

LLMは文章をそのまま一文として理解するのではなく、文字や単語のまとまりである**トークン**に分割して処理する。

例：「今日は大阪で働きます」という文章も、内部では複数のトークンに分解され、数値として扱われる。

Tokenizerのアルゴリズム自体を暗記させず、**AIは文章を細かな単位へ分解して処理している**ことを理解させる。

### 4.3 Embedding｜言葉を数値として扱う

各トークンはコンピュータが扱える数値の並びへ変換される。

この数値表現によって、単語同士の意味・使われ方・関係性を計算可能になる。

「王様」と「女王」、「東京」と「大阪」のように、使われる文脈が似た言葉は内部表現上でも関係を持つことを概念として扱う。

### 4.4 LLMの中心｜次のトークンを予測する

LLMの基本動作は、入力された文章とそれまでに生成した文章をもとに、**次にどのトークンが続きそうかを確率的に予測すること**である。

例：

> 日本の首都は

という入力に対して、学習した言語パターンから「東京」が続く可能性を高く予測する。

その後も、**1トークン生成 → その文章を再び入力として利用 → 次のトークンを予測**を繰り返して文章全体を作る。

重要なのは、LLMが最初から完成した回答文を頭の中に持っているわけではないという点である。

### 4.5 TransformerとAttention

LLMでは主にTransformerという仕組みが使われる。

数式や内部実装には深入りしないが、**Attention（注意機構）**の考え方は扱う。

Attentionは、文章中の「どの情報とどの情報の関係を強く見るべきか」を計算する仕組みとして説明する。

例：

> 山田さんは佐藤さんに資料を渡した。彼は明日説明する予定だ。

という文章で、「彼」が誰を指す可能性が高いかを考える際に、前後の単語の関係を見るイメージを使う。

これによって、離れた位置にある単語や文章同士の関係も扱える。

### 4.6 学習（Training）と利用（Inference）の違い

#### 学習時

大量の文章を使い、途中までの文章から次のトークンを予測させる。

予測が外れた場合はモデル内部の多数のパラメータを少しずつ調整し、予測精度を高める。

これを大量に繰り返すことで、文章のパターン、知識、推論に使える関係性等がパラメータへ反映される。

#### 利用時（推論）

ユーザーが入力したプロンプトと会話履歴等をコンテキストとして受け取り、すでに学習済みのパラメータを使って次のトークンを生成していく。

通常の会話中に、ユーザーとの会話だけで基礎モデルそのものがその場で再学習しているわけではないことも理解させる。

### 4.7 コンテキストウィンドウ

LLMが1回の処理で参照できる入力・会話・資料には上限がある。

この参照範囲を**コンテキストウィンドウ**として扱う。

LLMの回答は、

- 事前学習で得たパラメータ
- 今回のプロンプト
- 会話履歴
- 添付資料
- ツール等から取得した情報

などをもとに生成される。

「AIは何でも永久に覚えている」という誤解を避ける。

### 4.8 なぜハルシネーションが起こるのか

LLMは「正しい事実を必ず検索して返す仕組み」ではなく、**文脈上もっともらしい次のトークンを生成する仕組み**である。

そのため、情報が不足していても、文章として自然な続きを作ってしまう場合がある。

単に「AIは間違えるから注意」と覚えさせるのではなく、**次トークン予測 → もっともらしい文章を作れる → もっともらしい誤情報も作れる**という因果関係で理解させる。

### 4.9 同じ質問でも回答が変わる理由

LLMは次トークン候補に確率を持つため、設定やモデルによっては毎回完全に同じ文章になるとは限らない。

temperature等のパラメータ名の暗記は不要だが、**生成AIは決められた文章をコピーしているのではなく、その都度生成している**ことを理解させる。

### 4.10 LLM単体と外部情報・ツール

LLM単体には限界があるため、実際のAIサービスでは外部機能を組み合わせることがある。

概念として以下を紹介する。

- Web検索：最新情報を取得する
- RAG：社内資料や指定資料を検索して回答へ利用する
- Tool / Function Calling：計算、メール、カレンダー、DB等の外部機能を呼び出す
- MCP・Connector：外部システムやデータとの接続を支援する

詳細は後続テーマで扱い、Theme 07では**「LLM自身の知識・生成能力」と「外部から取得した情報」を区別する**ことを重視する。

### 4.11 生成AIでできること

- 情報整理・要約
- アイデア出し
- 文章作成・修正
- 調査の補助
- データ整理・分析補助
- 画像・動画等の生成
- コード生成・開発支援

### 4.12 人とAIの役割分担

**AI：大量の情報からパターンを使い、速く候補を作る・整理する・変換する**

**人：目的を決める・必要な事実を与える・状況を理解する・判断する・確認する・責任を持つ**

この役割分担をVEXUMの仕事へ接続する。

## 5. 扱わない内容

ただし、**トークン、Embedding、次トークン予測、Attention、Training / Inference、コンテキスト、ハルシネーション**は基礎知識として省略しない。

## 6. 推奨学習構成

**AIとは → 生成AI → LLM → トークン → Embedding → 次トークン予測 → Attention → 学習の仕組み → 回答生成 → ハルシネーション → 外部情報との接続 → 人との役割分担**

「AIはすごい」で終わらず、入力から出力までの流れを図で一本につなげる。

推奨図：

**文章入力 → Tokenize → Embedding → Transformer / Attention → 次トークン確率 → 1トークン生成 → 繰り返し → 回答**

その後に、**LLM + 検索 / RAG / Tools → 実務で使うAIサービス**という2段構造を見せる。

## 7. 実演

### 実演1｜次の言葉を予測する

講師が「昔々、あるところに」等の文章を途中まで提示し、受講者に次の言葉を予想させる。

複数の候補が成立することを確認したうえで、LLMも巨大な規模で類似した予測を行っていることにつなげる。

### 実演2｜情報不足によるハルシネーション

架空の会社・人物等についてAIへ質問し、モデルが推測する場合があることを見せる。

その後、正しい資料を渡す・検索させる等で回答が改善することを比較する。

## 8. 演習

### 演習1｜回答生成の流れを並べる

以下を正しい順に並べさせる。

- トークン化
- 数値表現へ変換
- 文脈を参照する
- 次のトークン候補を計算する
- トークンを生成する
- 繰り返して文章を作る

### 演習2｜AIの回答はどこから来たか

複数の回答例を示し、

- LLMの学習済み知識
- ユーザーが渡した情報
- 外部検索・資料
- 推測の可能性

のどれが関係していそうか考えさせる。
