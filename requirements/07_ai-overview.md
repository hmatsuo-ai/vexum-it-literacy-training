# Theme 07｜AIとは何か

- 区分：SEMINAR-CORE
- 想定受講段階：Theme 02の次
- 教材化時の想定：**AI全体の導入 + LLMを約4ページ**

## 1. このテーマの目的

AIを難しい技術用語として覚えるのではなく、**「AIはどのような仕組みで動き、なぜ自然な回答ができるのか。その一方で、なぜ間違えるのか」**を理解する。

特にLLMは、今後生成AIを使ううえで基礎となるため、単なる用語紹介では終わらせない。

**入力された文章を細かな単位に分け、文脈を参照しながら次に続く可能性の高い情報を予測し、それを繰り返して文章を作っている**という基本構造を、受講者が自分の言葉で説明できる状態を目指す。

## 2. 対象者・前提知識

Theme 01〜02を受講済み。AI経験は問わない。

数式、機械学習、プログラミングの専門知識は前提にしない。

ただし、LLMを「何となく答えてくれる魔法の箱」のまま使わせない。

## 3. 到達目標

受講者が次を説明できることを目標とする。

- AI・生成AI・LLMの関係
- LLMが検索エンジンや巨大なFAQデータベースそのものではないこと
- トークンとは何か
- LLMが次のトークンを予測しながら文章を生成すること
- EmbeddingとAttentionが何のためにあるかを概念的に説明できること
- 学習（Training）と利用（Inference）の違い
- コンテキストとは何か
- なぜハルシネーションが起こるのか
- LLMそのものと、AIアプリに追加された検索・資料参照等の機能は別であること
- AIの回答を人が確認する必要がある理由

略語や技術名を暗記することではなく、**一連の流れとして理解すること**を重視する。

## 4. 必須学習内容

### 4.1 AI・生成AI・LLMの関係

- **AI**：認識、予測、生成、判断補助などをコンピュータで行う技術の総称
- **生成AI**：文章・画像・音声・動画・コード等を新しく生成するAI
- **LLM（Large Language Model）**：大量の文章から言語のパターンを学習し、文章の理解・生成に利用される大規模言語モデル

LLMは生成AIの一種であり、多くの対話型生成AIの中核として利用されている。

### AIの歴史｜ここだけ押さえる

詳細な年表は扱わない。

**2022年に対話型生成AIが一般利用者へ急速に普及し、生成AIが日常業務でも使われる存在になった**という転換だけを1〜2分で説明する。

歴代モデル、企業別の製品史、リリース順は学習対象にしない。

## 5. LLMは約4ページ使って理解させる

LLMはTheme 07の中心として、**教科書で約4ページ**を確保する。

ページ数を増やして技術用語を詰め込むのではなく、以下の4段階で理解を積み上げる。

### Page 1｜LLMとは何か・何をしているのか

#### 伝えること

LLMは、質問に対する正解文をデータベースからそのまま取り出しているわけではない。

文章を細かな単位に分け、これまでの文脈をもとに、**「次に何が続きそうか」**を予測し続けて文章を生成する。

#### 必須用語

- LLM
- トークン
- 次トークン予測

#### 例

> 日本の首都は

という文章の続きとして、「東京」が続く可能性が高いと予測するイメージを使う。

その後も、

**1トークン生成 → 生成した内容も含めて次を予測 → また生成**

を繰り返して文章全体を作る。

#### このページで理解してほしいこと

**LLMは「完成した答えを検索して返す」のではなく、その場で文章を生成している。**

---

### Page 2｜文章をどうやって扱っているのか

#### トークン

LLMは文章をそのまま一文として処理するのではなく、文字や単語のまとまりである**トークン**に分けて扱う。

Tokenizerの方式や細かな分割規則は覚えさせない。

#### Embedding

トークンは、コンピュータで計算できる数値表現へ変換される。

この数値表現によって、言葉の意味や使われ方の関係を計算できるようになる。

Embeddingという名称は紹介するが、ベクトル計算や次元数は扱わない。

#### Attention

文章の中で、**どの言葉とどの言葉の関係を強く見るべきか**を扱う考え方として説明する。

例：

> 山田さんは佐藤さんに資料を渡した。彼は明日説明する予定だ。

「彼」が誰を指すかを考えるとき、前後の文脈を見るイメージで説明する。

Transformerという名称は紹介してよいが、内部構造・数式・行列計算には進まない。

#### このページで理解してほしいこと

**LLMは単語を文字列のまま扱うのではなく、数値化し、前後の関係を見ながら次の言葉を決めている。**

---

### Page 3｜LLMはどうやって賢くなり、何を見ながら答えるのか

#### 学習（Training）

大量の文章を使い、途中までの文章から次のトークンを予測する練習を大量に行う。

予測が外れた場合にモデル内部を調整し、それを繰り返すことで言語パターンやさまざまな関係を学習する。

誤差逆伝播、勾配降下法、パラメータ更新の数式は扱わない。

#### 利用（Inference）

ユーザーがAIを使って質問しているときは、基本的に学習済みのモデルを使って回答を生成している。

通常の会話をするたびに、その場で基礎モデルそのものを一から再学習しているわけではない。

#### コンテキスト

回答時には、現在のプロンプト、会話履歴、添付資料など、その時点で参照できる情報を使う。

AIが一度見たすべての情報を永久に保持し続けているわけではないことを理解させる。

#### このページで理解してほしいこと

**学習して身につけた能力と、その場で渡された情報を使って回答している。**

---

### Page 4｜なぜ間違えるのか・AIアプリとの違い

#### ハルシネーション

LLMは「正しい事実だけを必ず返す装置」ではなく、文脈上もっともらしい続きを生成する。

そのため、情報が不足している場合でも自然な文章を作れてしまい、結果として**もっともらしい誤情報**を生成することがある。

次の因果関係で理解させる。

**次トークン予測 → 自然な文章を作れる → 正しい情報が不足していても続きを作れる → ハルシネーションが起こり得る**

#### 同じ質問でも回答が変わる理由

次に続く候補には複数の可能性があるため、同じ質問でも毎回完全に同じ文章になるとは限らない。

`temperature` 等の設定名は暗記させない。

#### LLMとAIアプリは同じではない

現在のAIアプリには、Web検索、ファイル参照、外部サービスとの連携などが最初から組み込まれている場合がある。

Theme 07では、その内部方式や技術名称には触れない。

理解させるのは、

**LLMそのものの生成能力 ≠ AIアプリが追加で利用できる情報・機能**

という点だけとする。

RAG、Tool / Function CallingはTheme 07では扱わない。
MCP等の接続方式は後続テーマで扱う。

#### このページで理解してほしいこと

**AIの文章が自然であることと、その内容が正しいことは別。だから人による確認が必要。**

---

## 6. 4ページを通した一本の理解

受講者には最終的に、次の流れを説明できるようにする。

**文章入力**
→ **トークンに分ける**
→ **数値として扱う**
→ **文脈の関係を見る**
→ **次に続くトークンを予測する**
→ **1トークン生成する**
→ **これを繰り返して回答を作る**

そして、

**もっともらしい文章を生成する仕組みだから、もっともらしい間違いも起こり得る**

までつなげる。

教材では、この一連の流れを1枚の図として何度か再利用する。

## 7. 生成AIでできることと人の役割

### 生成AIでできること

- 情報整理・要約
- アイデア出し
- 文章作成・修正
- 調査の補助
- データ整理・分析補助
- 画像・動画等の生成
- コード生成・開発支援

### 人とAIの役割分担

**AI：大量の情報からパターンを使い、速く候補を作る・整理する・変換する**

**人：目的を決める・必要な事実を与える・状況を理解する・判断する・確認する・責任を持つ**

LLMの仕組みを理解したうえで、「AIの回答をそのまま正解として扱わない」という実務行動へつなげる。

## 9. 実演

### 実演1｜次の言葉を予測する

講師が、

> 昔々、あるところに

等の文章を途中まで提示し、受講者に次の言葉を予想させる。

複数の候補が成立することを確認し、LLMの次トークン予測につなげる。

### 実演2｜情報不足とハルシネーション

架空の会社や人物について質問し、AIが推測してしまう可能性を見せる。

その後、正しい資料を与える、またはAIアプリに利用可能な確認機能がある場合は情報を確認させ、回答がどう変わるかを見る。

ここでもRAG等の技術名称は出さない。
